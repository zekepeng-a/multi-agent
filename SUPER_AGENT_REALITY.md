# SUPER_AGENT_REALITY.md

**Status:** CURRENT REALITY MAP — INITIAL  
**Branch:** `super-agent/constitution-v0.1`  
**Purpose:** prevent proposed Super Agent concepts from being mistaken for implemented capability.

## 1. What exists now

### Project Control OS
A bounded control-plane prototype is implemented and G8 is COMPLETE at the previously reviewed milestone.

Implemented/partially implemented control areas include Project/Goal/Task/Acceptance, Run/Attempt, Command, Policy/Approval, Effect/reconciliation, Workspace, Evidence/Verification, Decision, Project-control Memory, Context Capsule, persistence and runtime adapter boundaries.

Its own current-reality labels remain authoritative in `PROJECT_ARCHITECTURE.md`.

### Legacy DSH Multi-Agent Runtime V0.5
A frozen historical research/runtime implementation exists at the repository root.

It contains Planner/Manager orchestration, Agent Registry, executors, DAG scheduling, validation/review/replan, derived memory/retrieval/context and runtime state files.

It is not future architecture authority.

## 2. What does not exist yet

The following are **NOT IMPLEMENTED as a new Super Agent architecture**:
- accepted Super Agent constitution;
- Adaptive Execution Engine V1;
- execution complexity router;
- benchmark proving multi-agent advantage;
- new single-agent/workflow/multi-agent strategy interface;
- accepted migration plan from V0.5 assets;
- integrated production workbench;
- live DSH product integration under the new architecture;
- Codex/Claude provider integrations under a new Super Agent contract.

## 3. Current governance state

Authorized now:
- reference research;
- legacy audit;
- constitution drafting/challenge;
- benchmark/evaluation design;
- architecture archaeology.

Not authorized yet:
- Execution Engine implementation;
- V0.5 feature development;
- rewriting Project Control OS to fit a runtime;
- declaring a new top-level architecture accepted;
- creating implementation phases beyond the research/constitution gate.

## 4. Critical uncertainty

The central open question is not “which multi-agent framework should we use?”

It is:

> What is the minimum architecture that measurably improves large-project completion beyond a strong single-agent + tools + Project Control baseline?

Until that is answered, complexity remains candidate, not capability.
